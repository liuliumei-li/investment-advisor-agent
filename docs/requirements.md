## 2. 项目概述

### 2.1 项目背景

大语言模型(LLM)在自然语言处理、多轮对话推理、复杂问题拆解上的突破,正推动证券投顾业务从"工具辅助"向"智能协作"演进。传统投顾模式依赖顾问个人经验与静态研报,存在服务半径有限、个性化程度不足、响应效率低等痛点。同花顺问财基于自研金融大模型 HithinkGPT,通过多智能体协作机制统一整合数据查询、选股分析、研判解读等能力,其开放的 SkillHub 智能体编排框架与金融数据 API 为构建个性化投顾系统提供了基础。

### 2.2 项目目标

构建一套由第三方大模型统一调度、多智能体协同服务的个性化证券投顾智能体系统,实现"语义理解 → 信息检索 → 策略生成 → 持续学习"的完整闭环,解决以下四大核心问题:

| 编号 | 核心问题 |
|---|---|
| P1 | 用户画像与风险偏好建模:多元信息分散、表达模糊,难以形成可量化的投资偏好参数 |
| P2 | 多投顾场景与多智能体协同决策:各场景分析逻辑差异大,需统一的"1+N"协同框架 |
| P3 | 数据实时性、准确性与幻觉控制:大模型幻觉可能编造财务数据、估值指标或市场信息 |
| P4 | 系统稳定性与高并发处理:高并发与市场剧烈波动下的响应能力、可用性保障 |

### 2.3 项目范围

**In Scope(基线内):**

- 用户画像与风险偏好分析(问卷 / 对话 / 持仓历史多渠道建模)
- 六类投顾场景:大盘研判、行业配置、个股分析、ETF 基金筛选、可转债投资、资产组合优化
- 多智能体协同决策(1 个主协调智能体 + 4 类专业智能体)
- 投资建议可视化与解释系统(逻辑链展开、数据溯源、风险提示)
- 数据实时性保障、数据溯源与幻觉检测纠正
- 合规审核与风险提示
- 高并发(≥100 用户)与稳定性保障

**Out of Scope(基线外,团队可自愿扩展):**

- 真实证券交易下单与持仓管理功能
- 移动端原生 App
- 付费订阅、商业化运营功能
- 对机构客户(iFinD 级别)的深度投研工作台

### 2.4 技术约束

| 编号 | 约束 |

## 4. 用户故事

### 4.0 组织说明

- 用户故事按 7 个 Epic(E1~E7)分组,共 30 条(US-01 ~ US-30)。
- 每条故事格式:**故事语句 + 验收标准(AC,可测试) + 关联规则 + 关联用例 + 优先级与 Issue 建议**。
- **优先级(MoSCoW)划分原则**:与赛题评分指标直接相关 → **Must**;源文档未硬性要求但显著增强体验 → **Should**;团队自愿扩展 → 不纳入基线。
- **Issue 映射约定**:1 条 US 对应 1 个 GitHub Issue,验收标准直接复制为 Issue 的 checklist(见附录 A)。

### 4.1 Epic E1:用户画像与风险偏好分析

> 对应赛题问题 P1、任务清单 F1。

#### US-01 问卷评估建立风险画像

- **故事**:作为个人投资者(R-01),我想通过在线问卷完成风险测评,以便系统标准化地了解我的风险偏好与投资目标。
- **验收标准**:
  - AC-1:问卷覆盖风险承受能力、收益预期、投资期限、投资经验等维度;
  - AC-2:提交后系统自动生成风险等级(按 BR-IMG-01 五档输出)与画像要素;
  - AC-3:测评结果可保存并与用户账户关联,可再次查看;
  - AC-4:问卷作答过程 ≤10 分钟,结果生成 ≤5 秒。
- **关联规则**:BR-IMG-01、BR-IMG-02、BR-IMG-03
- **关联用例**:UC-01
- **优先级**:Must | **Issue 规模建议**:M

#### US-02 自然语言对话建立画像

- **故事**:作为个人投资者(R-01),我想通过自然语言对话描述我的投资情况与需求,以便系统从非结构化表述中理解我的偏好。
- **验收标准**:
  - AC-1:系统能从对话中抽取风险承受、收益预期、投资期限等画像要素(语义理解与信息抽取);
  - AC-2:对表述模糊的信息,系统主动追问澄清(如"您能承受多大比例的短期回撤?");
  - AC-3:对话提取结果与问卷/持仓来源合并为同一画像(不互相覆盖丢失);
  - AC-4:对话结束后可预览本次更新了哪些画像要素。
- **关联规则**:BR-IMG-02、BR-IMG-03、BR-IMG-05
- **关联用例**:UC-01
- **优先级**:Must | **Issue 规模建议**:L

#### US-03 持仓历史分析

- **故事**:作为个人投资者(R-01),我想导入或描述历史持仓,以便系统分析我的持仓习惯并校准画像。
- **验收标准**:
  - AC-1:支持文本描述、持仓清单粘贴、结构化文件导入(如 CSV)中至少两种方式;
  - AC-2:系统分析持仓集中度、资产类别分布、换手特征并输出结论;
  - AC-3:持仓分析结论纳入画像模型(如实际持仓风险水平与自评风险等级偏差明显时提示用户);
  - AC-4:导入失败或格式异常时给出明确错误提示。
- **关联规则**:BR-IMG-02、BR-IMG-03、BR-IMG-06
- **关联用例**:UC-01
- **优先级**:Must | **Issue 规模建议**:M

#### US-04 可视化风险画像报告

- **故事**:作为个人投资者(R-01),我想查看可视化的风险画像报告,以便了解系统对我的判断并确认或修正。
- **验收标准**:
  - AC-1:报告以图表展示风险等级、收益预期、投资期限、持仓习惯等要素;
  - AC-2:展示画像各要素的推断依据来源(问卷 / 对话 / 持仓,符合 BR-DAT-04 溯源要求);
  - AC-3:支持用户确认画像或修正个别要素,修正后画像立即生效;
  - AC-4:报告可在后续会话中随时调出查看。
- **关联规则**:BR-IMG-01、BR-IMG-04、BR-IMG-05
- **关联用例**:UC-01
- **优先级**:Must | **Issue 规模建议**:M

#### US-05 画像动态更新

- **故事**:作为个人投资者(R-01),我希望我的画像随新增信息和行为变化持续更新,以便建议始终匹配我的当前状态。
- **验收标准**:
  - AC-1:用户新增重要信息(新问卷、新持仓、对话中的重大变化表述)时触发画像更新;
  - AC-2:画像更新后,后续建议按新画像生成;
  - AC-3:更新历史可追溯(何时、因何更新、由哪一要素变化引起)。
- **关联规则**:BR-IMG-06
- **关联用例**:UC-01
- **优先级**:Should(赛题未硬性要求,属于"持续学习"闭环的增强) | **Issue 规模建议**:M

### 4.2 Epic E2:多场景投顾分析与建议生成

> 对应赛题期望「全场景覆盖」、技术要求 T1、任务清单 F2。

#### US-06 大盘研判

- **故事**:作为个人投资者(R-01),我想咨询大盘走势研判,以便了解市场整体环境后再做决策。
- **验收标准**:
  - AC-1:输出包含市场整体走势解读、关键影响因素与风险提示;
  - AC-2:研判基于实时行情与财经资讯,引用数据可溯源(BR-DAT-04);
  - AC-3:研判结论带清晰的逻辑链条,支持逐级展开(联动 US-21);
  - AC-4:结合用户画像给出与其风险等级匹配的操作提示(如仓位方向)。
- **关联规则**:BR-ADV-01、BR-ADV-03、BR-ADV-04、BR-DAT-01
- **关联用例**:UC-02、UC-07
- **优先级**:Must | **Issue 规模建议**:L

#### US-07 行业与概念追踪

- **故事**:作为个人投资者(R-01),我想获取行业/概念板块的追踪分析与配置建议,以便把握板块轮动机会。
- **验收标准**:
  - AC-1:支持对指定行业/概念板块输出景气度、资金流向、政策催化等维度分析;
  - AC-2:输出行业配置建议并说明与用户画像的匹配理由;
  - AC-3:分析数据带时间戳,注明数据时效(BR-DAT-03);
  - AC-4:板块分析包含下行风险提示。
- **关联规则**:BR-ADV-01、BR-ADV-03、BR-ADV-04、BR-DAT-03
- **关联用例**:UC-02、UC-07
- **优先级**:Must | **Issue 规模建议**:L

#### US-08 个股分析

- **故事**:作为个人投资者(R-01),我想获得指定个股的深度分析,以便支持买卖决策。
- **验收标准**:
  - AC-1:覆盖基本面(财务数据、估值)与技术面/行情面(走势、资金)分析;
  - AC-2:所有财务数据、估值指标须来自可信数据源并可溯源,不得编造(BR-DAT-05);
  - AC-3:输出包含明确的风险提示,标注分析局限(如"基于公开数据,不含未公开信息");
  - AC-4:结合用户画像给出个股在其组合视角下的参考建议(如仓位上限)。
- **关联规则**:BR-ADV-01、BR-ADV-04、BR-DAT-04、BR-DAT-05、BR-CMP-01
- **关联用例**:UC-03、UC-07
- **优先级**:Must | **Issue 规模建议**:L(可拆 2 个 Issue:基本面分析 / 技术面与组合建议)

#### US-09 ETF 基金筛选

- **故事**:作为个人投资者(R-01),我想按条件筛选 ETF 基金,以便找到符合我风险偏好的基金品种。
- **验收标准**:
  - AC-1:支持按资产类别、行业主题、规模、费率、跟踪误差等条件筛选;
  - AC-2:筛选结果与用户风险等级匹配排序(按 BR-IMG-04 匹配矩阵);
  - AC-3:每个基金展示关键指标与数据来源;
  - AC-4:输出基金配置建议与风险提示。
- **关联规则**:BR-ADV-01、BR-ADV-03、BR-IMG-04、BR-DAT-04
- **关联用例**:UC-04、UC-07
- **优先级**:Must | **Issue 规模建议**:M

#### US-10 可转债投资分析

- **故事**:作为个人投资者(R-01),我想获得可转债投资分析,以便参与转债品种的投资决策。
- **验收标准**:
  - AC-1:覆盖转债价格、转股价值、溢价率、正股关联等核心指标分析;
  - AC-2:输出可转债投资建议并说明适配的用户风险等级;
  - AC-3:包含强赎、破发等特有风险提示;
  - AC-4:引用数据可溯源且带时效标注。
- **关联规则**:BR-ADV-01、BR-ADV-03、BR-DAT-03、BR-DAT-04
- **关联用例**:UC-05、UC-07
- **优先级**:Must | **Issue 规模建议**:M

#### US-11 资产组合优化

- **故事**:作为个人投资者(R-01),我想获得对我现有持仓的资产组合优化建议,以便改善持仓结构。
- **验收标准**:
  - AC-1:基于用户持仓(来源见 US-03)分析集中度、风险暴露与收益特征;
  - AC-2:输出优化建议(调仓方向、目标配置比例),比例范围符合 BR-IMG-04 匹配矩阵;
  - AC-3:优化建议说明每一处调整的理由与数据依据;
  - AC-4:提示调仓成本、税费等现实约束与风险。
- **关联规则**:BR-ADV-01、BR-ADV-04、BR-IMG-04
- **关联用例**:UC-06
- **优先级**:Must | **Issue 规模建议**:L

#### US-12 个性化投资建议与资产配置方案

- **故事**:作为个人投资者(R-01),我想获得结合我的风险画像量身定制的投资建议与资产配置方案,以便获得非泛化的指导。
- **验收标准**:
  - AC-1:生成的建议必须引用用户画像要素并说明匹配理由(禁止无差别通用建议);
  - AC-2:资产配置方案给出大类资产比例区间,与用户风险等级匹配(BR-IMG-04);
  - AC-3:方案包含收益预期区间、投资期限适配说明与风险提示;
  - AC-4:同一问题对不同风险等级用户输出的建议存在可解释的差异。
- **关联规则**:BR-ADV-04、BR-IMG-04、BR-CMP-01
- **关联用例**:UC-06、UC-09
- **优先级**:Must | **Issue 规模建议**:L

#### US-13 结构化投资分析报告

- **故事**:作为个人投资者(R-01)与投资顾问(R-02),我想获得结构化的投资分析报告,以便快速把握关键信息并用于决策或客户服务。
- **验收标准**:
  - AC-1:报告按固定结构输出:核心结论、分析过程、数据依据、风险提示;
  - AC-2:报告支持导出(如 Markdown/PDF)与界面内阅读两种形态;
  - AC-3:报告各章节与数据来源一一对应,可跳转溯源;
  - AC-4:多场景分析结果(US-06~11)可组装为一份完整报告。
- **关联规则**:BR-ADV-01、BR-ADV-05、BR-DAT-04
- **关联用例**:UC-02 ~ UC-06
- **优先级**:Must | **Issue 规模建议**:M

### 4.3 Epic E3:多智能体协同决策

> 对应赛题问题 P2、技术要求 T2、任务清单 F3。

#### US-14 主协调智能体统一调度(1+N 架构)

- **故事**:作为个人投资者(R-01),我希望系统由主协调智能体统一调度多个专业智能体,以便一站式获得完整、一致的投顾结论。
- **验收标准**:
  - AC-1:系统按"1 个主协调智能体 + N 个专业智能体"架构运行(BR-AGT-01);
  - AC-2:主协调智能体完成请求解析、任务分解、分派与结果聚合;
  - AC-3:用户无感知任务编排细节,交互入口统一;
  - AC-4:任一专业智能体异常时主协调智能体按降级策略输出并如实告知(联动 BR-PER-04)。
- **关联规则**:BR-AGT-01、BR-AGT-02、BR-PER-04
- **关联用例**:UC-07
- **优先级**:Must | **Issue 规模建议**:L

#### US-15 专业智能体群

- **故事**:作为个人投资者(R-01),我希望宏观研究、行业分析、个股研究、基金配置等专业智能体各司其职,以便每个分析维度都具备专业性。
- **验收标准**:
  - AC-1:系统具备宏观研究、行业分析、个股研究、基金配置 4 类专业智能体;
  - AC-2:各智能体有明确职责边界与专属数据源/工具;
  - AC-3:各智能体输出符合统一的结果结构规范,可被主协调智能体聚合;
  - AC-4:新增专业智能体可通过配置方式接入(可扩展性)。
- **关联规则**:BR-AGT-01、BR-DAT-01
- **关联用例**:UC-07
- **优先级**:Must | **Issue 规模建议**:L(可拆 4 个 Issue:每类智能体一个)

#### US-16 交叉验证与一致性校验

- **故事**:作为个人投资者(R-01),我希望投资建议经过多智能体交叉验证与一致性校验,以便结论可信、不自相矛盾。
- **验收标准**:
  - AC-1:关联智能体的结论须执行交叉验证(如宏观判断与行业建议的一致性);
  - AC-2:校验覆盖:事实一致性(引用的同一数据不得冲突)、逻辑一致性(结论与前提不矛盾);

### 7.3 MoSCoW 优先级

| 优先级 | 判定标准 | 基线条目 |
|---|---|---|
| Must | 与赛题评分指标、硬性指标直接相关 | US-01 ~ US-04、US-06 ~ US-30(共 29 条) |

| Could | 团队自愿扩展 | 不纳入基线(如建议导出分享、行情预警、移动端适配等) |

说明:赛题说明书对功能要求非常明确,故基线以 Must 为主;Should 条目在 Sprint 排期紧张时可延后而不影响赛题验收。

### 7.4 迭代划分建议(Sprint → GitHub Milestone)

| Sprint | 主题 | 范围 | 里程碑产出 |
|---|---|---|---|
| Sprint 1 | 画像与基础架构 | E1(US-01 ~ US-05)、UC-01、SkillHub 基础框架搭建 | 可用画像流程(问卷/对话/持仓 → 画像报告) |
| Sprint 2 | 多场景投顾分析 | E2(US-06 ~ US-13)、UC-02 ~ UC-06 | 六类场景可用,输出结构化报告与个性化建议 |
| Sprint 3 | 多智能体协同决策 | E3(US-14 ~ US-18)、UC-07 | "1+N"协同架构上线:分解、并发、交叉验证、分歧处理 |
| Sprint 4 | 可视化交互与数据质量 | E4(US-19 ~ US-22)、E5(US-23 ~ US-25)、UC-08 | 解释面板、逻辑链溯源、幻觉检测生效 |

每个 Sprint 对应一个 GitHub Milestone,US 为其中的 Issue。Sprint 5 的测试报告同时满足赛题提交材料中"系统测试报告"的要求。

## 8. 附录

### 附录 A:GitHub Issue 拆分规范

#### A.1 拆分约定

1. **1 条 US = 1 个 Issue**;US 标注"可拆 N 个 Issue"的(US-08、US-15、US-19),拆分后在 Issue 中互链。
2. Issue 标题格式:`[E{n}] US-{nn} {标题}`,例如 `[E1] US-01 问卷评估建立风险画像`。
3. 验收标准直接复制为该 Issue 的 checklist,完成 = 全部勾选 + 对应测试通过。
4. 每个 Issue 关联 Milestone(对应 Sprint,见 7.4)。

#### A.2 Issue 模板

```markdown
## 背景
需求基线 v1.0 §4.x <US 链接>

## 验收标准
- [ ] AC-1 ...
- [ ] AC-2 ...

## 关联
- Epic: E1
- 优先级: Must
- 规模: M
- 关联用例: UC-01
- 关联业务规则: BR-IMG-01、BR-IMG-02
```

#### A.3 标签体系

| 标签类别 | 取值 |
|---|---|
| epic | `epic:e1` ~ `epic:e7` |
| priority | `priority:must`、`priority:should` |
| size | `size:s`、`size:m`、`size:l` |
| type | `type:feature`(功能)、`type:tech-debt`(基建/重构)、`type:test`(测试报告等) |

#### A.4 大 US 子任务拆分示例(US-08 个股分析)

- 子任务 1:行情与财务数据接入与缓存(关联 US-23)
- 子任务 2:基本面分析智能体(估值、财务指标计算)
- 子任务 3:技术面/行情面分析智能体
- 子任务 4:幻觉校验与风险提示注入(关联 US-25、UC-09)
